# 多模态制作：逐镜生成与实拍合成的两条工作路线

研究日期：2026-09-08。目的：为商品视频、品牌片和返修 Skill 提供操作者证据；不把教程样片说成真实投放效果，也不把计划中的接口说成已接通。

## 1. Caleb：先建立可用参考，再逐镜选择

- **产品多角度参考先于场景。** 00:43–03:28 区分虚构概念商品与已有真实商品；真实商品已有照片时应从那些素材开始。多角度覆盖是减少后续猜测的手段，不代表模型生成的背面可以升级成真实 SKU 证据。[00:43](https://www.youtube.com/watch?v=qJiwXH2h7ps&t=43s)
- **身份、穿着和视觉世界分开核对。** 03:29–05:51 用本人多角度资料和服装参考；07:42–08:48 比较多图的色调与相机观感。样片中重复视角、缺头、脸变建筑都被指出，说明“有四张图”与“参考有效”不是一回事。[03:29](https://www.youtube.com/watch?v=qJiwXH2h7ps&t=209s)
- **先修有问题的静帧，再投入视频生成。** 10:46–11:59 讲拆开场景图、用原先的参考补修人物。12:01–14:53 再用选定图作视频起始帧、比较不同 take。批量输出后仍需要选择，不是所有输出都进入剪辑。[10:46](https://www.youtube.com/watch?v=qJiwXH2h7ps&t=646s)
- **剪辑和声音是最后的制作工作，不是模型输出顺便完成。** 16:02–17:30 讲时间线、图形、轻颗粒、音乐以及原生音效音量；18:14–18:21 仍指出有些镜头应替换。两小时半是个人样片自述，不是通用交付时限。[16:02](https://www.youtube.com/watch?v=qJiwXH2h7ps&t=962s)

采用边界：借鉴参考资产分工、逐镜审核和编辑流程，不照搬虚构毛衣的商品功能、生成次数、固定帧率、模型排名与订阅套餐。上采样不能修复错误 Logo、商品结构、身份或物理动作；需要回到相应的参考或局部镜头处理。

## 2. Albert 与 Robert：保留实拍，只生成真正需要的部分

- **为合成拍素材。** 01:30–03:41 讲接近目标观感的基底、稳定曝光和清晰的待合成区域；先定入点/出点。对于这条固定视角流程，稳定光线能减少合成难度；不把“不能有灯光变化”扩写成所有 VFX 的普遍限制。[01:30](https://www.youtube.com/watch?v=rpEKSa8LPrE&t=90s)
- **先解决空间、比例与遮挡，再追求细节。** 04:41–07:44 先用粗略轮廓表达马的位置、比例、姿态；10:09–13:48 只在需要的区域修补，保留原始背景。镜头里的对象要能站在那个空间里，不是生成一张独立好看的图。[04:41](https://www.youtube.com/watch?v=rpEKSa8LPrE&t=281s)
- **动作和机位分别写。** 14:08–17:59 要求生成层的相机保持静止，马先喝水再抬头；实际失败包括机位晃动、动作时机不对、河水方向错误。把方向写进提示不保证执行成功，需要检查画面。[14:08](https://www.youtube.com/watch?v=rpEKSa8LPrE&t=848s)
- **问题可以交给合成，不必反复整段生成。** 18:03–23:56 做位置/比例对齐和遮罩；24:12–28:57 将真实背景运动跟踪传给生成层，再匹配阴影与锐度。29:21–31:18 用更精细的主体遮罩和独立反射层，减少错误河水进入成片。[24:12](https://www.youtube.com/watch?v=rpEKSa8LPrE&t=1452s)

反例：完全生成的画面若同时漂移背景、产品和人物，不一定值得继续改提示词。已有好实拍且只需增加场景元素时，可以保留真实主体和动作，只生成局部。反过来，快速概念预演没有实拍源时，逐镜参考生成更直接。这里的合成流程需要编辑器、遮罩/跟踪能力与人工取舍，不是只靠调用一个模型。

## 3. 从上述方法推导的 Agent 操作

以下是本次设计的执行方法，不冒充作者已经交付的 Agent 系统。

|阶段|实际输入与操作|适合交给工具的部分|需要人的判断与退回条件|
|---|---|---|---|
|商品事实|指定 SKU、实物照片、可见规格/Logo、允许表达、真实使用方式；记录未知背面和隐藏功能。|建立事实表与文件对应关系；检查必需字段、来源、分辨率及版本。|事实是否成立、照片是否足以代表商品；无依据的结构/功效保持未知，不用生成图反证真实商品。|
|分镜|明确受众、用途、时长、比例；每镜写任务、入点状态、动作、出点状态、产品证据。|将批准脚本拆成镜头卡，检查时长和镜头/旁白对应；指出重复、缺失、状态矛盾。|故事是否能让人理解或想购买，镜头是否值得保留。教程一未教授完整编剧，因此商业叙事应由项目 brief 和已有 Skill 决定。|
|一致性|产品、人物、服装、场景分别绑定参考，不能互相替代；人物只在该镜出现时加载。|做引用和版本核对，抽取候选对比图；视觉模型可标疑似变形。|人脸、身材、材质和商品接触是否自然；自动相似分数或布尔标记不能单独验收。|
|镜头生成|根据素材选择逐镜生成或实拍加局部；机位动作与主体动作分开；先检查静帧。|组装请求、记录实际输入/输出、生成状态和成本；在明确预算内提交单镜。|运动、空间和节奏是否对；失败只重做该镜及真实依赖镜，不无限重试。|
|声音与剪辑|批准旁白、音乐权限、原声用途、镜头时码与剪辑工程。|转写、时间码、字幕、音轨存在性、峰值/静音段候选、编码参数检查；可生成声音候选。|语气、停顿、节奏、声画关系和音乐选择；有音轨不等于声音正确，重新配音不等于可以丢弃原现场声。|
|局部返修|明确 take、失败时间段、失败部位、原始参考、保留区域和前后帧。|制作返修单，切出上下文，限定重生成/补拍/合成对象，保存新旧版本。|判断是遮罩、跟踪、重新剪切、配音还是重拍更合适；保护原始素材，不把整片重生成当默认。|
|验收|交付规格、事实表、全部最终镜头、声音和来源授权。|文件存在/可解码、尺寸、时长、帧率、音轨、字幕版本以及审核表完整性检查。|整片从头播放；关键 SKU/人物/动作逐段核对。镜头可用于剪辑、格式合格与最终验收是三个状态。|

## 4. 怎样接现有能力，而不重造一套系统

### `jingqiu-DTC`

已完整读取本地 `SKILL.md`：它从商品事实、购买角度、创意/视觉规则到五格 16:9 故事版及英文 15/30 秒脚本。适合短商品创意规划；不能说调用它就已经生成了最终视频。其 validator 检查文件与合同，不证明画面真的是同一商品。公开项目：[jingqiu-DTC](https://github.com/meowdoone/jingqiu-DTC)。

### `brand-film-product-skill`

已完整读取本地 `SKILL.md` 和 runtime index：60/90 秒、18 镜、一条连续脚本、三张分板；默认故事板交付，只有明确要视频时才编译视频请求。产品、身份、动作和上一镜出口有独立引用角色。应沿用这些产物和 validator，不另造同名 run 格式；`fast_previs` 不能说成制作级终稿。公开时以可见项目入口说明为准，不泄露用户的本地身份和商品私有素材。

### `reframe-ai-video-rebuilder`

已读取[公开 README](https://github.com/meowdoone/reframe-ai-video-rebuilder)。它包含转写/解说重构/换轨及网页拆镜、重排、字幕功能，不是已验证的商品、人脸局部修补 API。特别注意：公开 `main.py` 默认裁成 9:16 并替换原声。横屏品牌片或要保留现场声时，不直接运行默认命令；先检查配置、选用合适编辑入口。元数据变更不能当作原创、实拍或授权证明。本次仅查文档，没有运行它的媒体处理或验证外部服务。

### 当前仓库的离线审核

已读 `scripts/review.py` 的 `shots` 分支：接收 `shot_id`、`product_ref`、`character_ref`、`take`、`reviewer`、`timecode`，以及审核者提供的商品/人物/动作/声音/授权布尔结果；输出 `REPAIR` 或 `READY_FOR_EDIT`。它不读取像素、不做人脸识别，不自动判断相似度，也不代表最终成片通过。未知项不能填 `true`，应留在待审任务中，待真实检查后再运行。

## 5. 交付与研究边界

- 记录实际读到的字幕，不把文字研究称作逐帧观察整条影片。本次没有复制完整字幕进公开仓库。
- AI 可以组织素材、编排请求、做技术检查并提出疑点；剪辑判断和商业表达仍需负责人审阅。
- 发布前单独核实真实 SKU、人物/声音/音乐授权及所需披露。原教程的发布许可不自动覆盖本项目。
- 不承诺固定模型最强、无限次数、固定成本或全自动返修。先查当下工具是否存在、输入格式/权限/预算是否满足；没有引擎时交付可用的制作包并清楚标注未生成视频。
