## 1. 各类投放不能只换平台名称

| 场景 | 先判断的购买路径 | 主要诊断 |
| --- | --- | --- |
| Google 搜索 → Web | 搜索词 → 承诺相符页面 → 商品/表单 → 有效订单或合格机会 | 词的意图与可服务地区、页面是否对应需求、实际合格结果、预算受限还是排名/转化受限 |
| Meta → Web | 场景/问题 → 证明与报价 → 页面 → 订单/线索质量 | 用户是否理解问题与产品价值；创意、报价和承接一致性；不能只凭点击率判赢家 |
| Apple 搜索 → App | 查询 → 商店商品页 → 安装/首次打开 → 使用 → 试用/付费 | 关键词与页面是否匹配；品牌/非品牌、安装与付费分开；App Store 搜索不是无限流量池 |
| Meta / Google 等 → App | 版位里的演示 → 商店页或合格深链 → 首次价值 → 订阅/留存 | 目标事件与真实付费之间的关系；操作系统、来源、版本、归因窗和试用成熟度 |
| Web → App / SaaS | 问题内容或工具体验 → 注册/支付 → 激活 → 持续使用 | 入口差异决定承接；自助订阅和销售线索分开；网页付款不代表完成 App 激活 |

P1 的 06:19–09:58、15:17–16:58 支持按真实转化与地区分配预算；P2 的 07:10–12:46 支持按用户理解程度调整信息；P3 的 30:51–37:01 支持按所用渠道选择测量工具；P4 支持搜索容量与商店页面匹配。上表是我们的联合整理，不是任何一位专家提出的完整统一框架。

## 2. 最值得用于运营决策的五个变量

### 目标、回收时间与现金

P3 先问为什么买量、能接受多久回收、能承担多少试验损失。现金紧张、必须短期回收与愿意为产品验证买样本，是不同任务。不能拿自然高意向用户的收入直接预测新渠道收入；原视频 27:27–30:04 专门讨论来源偏差。

**实施判断：** 尚未定义有效客户、回收窗口或最大损失 → 先补定义，只做数据整理；不推荐“先加预算再观察”。早期试验可以有预算，但目标明确标为学习，不伪装为盈利扩量。

### 创意是否回答了目标人群的问题

P2 03:38–12:46 用认知阶段解释：老客优惠信息可能不足以说服刚认识产品的人。P3 53:03–57:57 则主张先试明显不同的概念，再对有信号的概念细化。

**实施判断：** 创意之间只是颜色和字幕小改 → 先整理问题、场景、证据、演示与报价的实质差异。低 CTR 是线索，不是“模型知道画面哪里错了”。商品、功能、见证与数字都要有证据；商业素材保持明确广告身份。

### 当前流量还有多少可盈利空间

P1 04:01–04:44、08:19–10:34 先看稳定的转化与搜索覆盖，再逐步增加预算；15:17–16:58 演示将转化好但花费少的地区单独评估。P4 同时提醒搜索量与回报要求会限制 Apple 搜索扩量。

**实施判断：** 结果可接受但预算分配限制了已验证的细分群体 → 输出限额测试候选；若额外花费变贵、回收下降 → 查细分/页面/报价，不能无限加钱。展示份额低不自动等于“受预算限制”，还要核排名、资格和目标设置。

### 试用、付费与续订是否一起改善

P3 39:14–43:06 指出便宜的试用可能带不来付费，平台代理事件达标并不等于生意改善。

**实施判断：** 安装和试用增加但成熟批次付费没增加 → 检查来源质量、首个任务、付费墙、试用结束与退款；先修断点。订阅类按相同加入时间和观察时长看激活、试用转付费、续订与净收入，不能把最近用户尚未续订记为流失。

### 归因与整体经营是否能互相解释

P3 31:02–37:01 区分 Apple 自有归因、平台 SDK 与 MMP；39:14–47:55 同时看渠道明细与国家/系统层整体趋势。单渠道初期不必为工具而买 MMP，多渠道则要评估一致性与成本。

**实施判断：** 平台和产品/账单结果不一致 → 保留两种口径并解释窗口、去重、退款、建模与延迟；不能强行配成相等。自然用户很多时，整体低 CAC 也可能掩盖付费亏损；趋势比较只能支持假设，非随机对照不能直接称增量。

## 3. 分歧、限制与不采用的内容

- Aaron 的 4–6 周、每次约 20% 增幅及等待天数是其账户经验，不是跨业务默认阈值。来源样本量、转换延迟、成本和风险承受能力仍需单独检查。
- Ben 对“最先触达最容易转化者”的描述是解释模型，不是可验证的 Meta 内部执行顺序。掉量也可能由追踪错误、价格、缺货、页面、竞争或季节引起，不能一律诊断为素材不够好。
- Thomas 55:16–55:38 关于“花费集中者几乎总是赢家”的强断言不固化。分配花费是平台选择结果，不是随机试验；小样本和早期偏差不能因此消失。
- 2023 年 SDK、MMP、平台进入条件与最低预算经验不写成 2026 年现行规则。MMP 不是恢复全部用户轨迹的魔法，也不授权绕过同意或拼接被限制的身份。
- Web2App 的优势不是简单少付手续费；P5 强调入口、转化、留存与支付信任都会改变。不能把成熟品牌的复杂问卷照搬给所有 App，更不能承诺省费后必然更赚钱。
- 三位覆盖搜索、社交和订阅 App；没有单独完成 B2B 销售驱动 SaaS 的实操长课研究。SaaS 的 CRM 合格线索/机会/成交连接，是本次方法设计，不能标成这三条视频的已验证案例。

## 4. Agent 可以具体做什么

### 资料与工具映射

- Web：获授权广告报表中的 campaign/adset/ad/keyword/search term/placement ID；落地页版本；分析事件；真实订单或 CRM 合格线索与成交。事件名只是例子，读取当前事件字典后映射。
- App：国家、系统、版本、媒体来源、campaign/creative、归因类型/窗口；安装或首次打开、核心动作、试用、首次付款、续订、退款。Apple、MMP、产品分析和支付系统分别保留来源。
- 经营：同群体、同窗口的花费、实收/退款、平台与支付费、履约或服务可变成本。预测 LTV 与已实现收入分列。
- 所有原始导出注明观察时间和币种；不存在的字段不自动填零。访问或身份受限时使用用户提供的导出，不假装已有连接。

### 输出和检查

1. 校验字段、ID、窗口、去重键与群体是否相同；无法对账时返回缺口，不算看似精确的 ROI。
2. 输出“流量 → 创意/承诺 → 承接 → 激活/成交 → 留存/回收”哪一段异常及竞争解释。
3. 生成小范围实验卡：假设、唯一主改动、目标对象、预算/损失上限、观察窗口、成功与停止条件、批准人。观测性比较标明不能证明因果。
4. 输出改动候选，不直接改预算/出价/事件配置；实际账号写入必须有本次授权、当前权限、原值快照与执行后读取。
5. 报表截断、隐私抑制、跟踪断流、退款未到齐或群体太新 → 留在 RECONCILE / HOLD。安全预算上限可单独触发停止复核，不必等统计显著。

### 本仓库已有实现，不夸大范围

`scripts/review.py` 是离线 JSON 审查，不调用广告 API：

```sh
python3 scripts/review.py examples.json --example paid
python3 scripts/review.py examples.json --example cohorts
```

`paid` 要求同窗口、币种、收入基础、归因窗口与匹配群体，成本完整后计算广告后贡献；只给 `REVIEW_SCALE / REVIEW_CHANGE / REVIEW_STOP / HOLD / RECONCILE`。它没有统计显著性检验、素材视觉识别、预测 LTV、因果归因或账户执行功能。

`cohorts` 按同一 eligible 分母算激活、留存、付费；这些结果可重叠，不能相加，也不等于“激活后留存率”。未到观察期的群体不输出完成率。
