## 2. 专家真正提供了哪些可用做法

### 2.1 先研究问题，不先批量生产文章

Ethan 将站内与站外分开：站内回答功能、场景、集成、语言等具体问题；问题可来自搜索词、销售沟通和客户支持，再按主题合并。站外则分析目标问题实际引用哪些视频、社区、媒体或文章，不预设所有业务都去同一个地方铺量。[G1 15:47–16:32、21:54–24:39](https://www.youtube.com/watch?v=iT7kq-R3Gjc&t=947s)

Lily 的具体做法是查品牌问题，确认官网是否讲清产品、用途、比较、集成和公司事实，并按地区与受众补内容；不是给每个近似问句单独生成一页。[G2 30:14–33:23](https://www.youtube.com/watch?v=2nJkT8zOzcM&t=1814s)

**本项目落地**：每个主题保留原始问题、市场、用户阶段、现有答案 URL、缺失证据和拟修改位置。搜索量只是代理信号，不能直接当成某个问答产品的真实提问次数。

### 2.2 内容要能独立回答问题，并提供实际材料

Lily 认为不存在适配所有系统的固定切块技巧，更可控的是写清楚、脱离上下文仍能读懂的回答；音视频也要有可理解的文字资料。[G2 21:11–23:29](https://www.youtube.com/watch?v=2nJkT8zOzcM&t=1271s)

Ethan 批评互相重写文章，提出应思考是否提供了别人没有的信息。不过他在这段是在讨论可能的评价方法，**不能将“信息增量”或某种专家标记声称为已证实的排名公式**。[G1 25:19–27:43](https://www.youtube.com/watch?v=iT7kq-R3Gjc&t=1519s)

**本项目落地**：优先提供真实商品参数、操作步骤、演示、限制、比较依据和更新说明；每个结论回指原始资料。没有证据时列出待补项，不编测试、客户反馈或专家背书。

### 2.3 站外分发按来源设计，身份与商业关系要清楚

Ethan 介绍 Webflow 员工用真实身份、所属公司和有用答案参与社区的实践；他同时指出批量假账号、互赞和自动垃圾回复会遇到删除/封禁。应先找到与目标问题相关的讨论，再决定能贡献什么。[G1 16:45–19:11](https://www.youtube.com/watch?v=iT7kq-R3Gjc&t=1005s)

Lily 也建议以品牌身份回答真实问题，并用视频解释具体内容；提醒过度推广可能被社区拒绝。[G2 34:32–35:33](https://www.youtube.com/watch?v=2nJkT8zOzcM&t=2072s)

**本项目落地**：网站、视频、媒体合作和社区分别有内容形式、负责人和审核要求。媒体或联盟合作记录付费关系；不把商业安排包装成独立测评，更不保证对方会给出“最好”的评价。

### 2.4 引用变化不等于业务增长

Ethan 说明，同一问题多次询问、不同问法和不同产品界面会产生不同答案；建议分别跟踪。对 B2B，单看最后一次引荐访问会遗漏部分影响，可以补充客户自报来源，但那也不是精确因果归因。[G1 34:00–40:13](https://www.youtube.com/watch?v=iT7kq-R3Gjc&t=2040s)

Lily 将主题可见性、品牌相关信号、实际访问、参与和转化并列，并建议在分析工具中分组查看 AI 来源；她也提醒引用波动，以及不能只改日期假装更新内容。[G2 29:18–30:34、33:26–34:29](https://www.youtube.com/watch?v=2nJkT8zOzcM&t=1758s)

**本项目落地**：被发布、被索引、被提及、被引用、到站访问、合格行为分别存证。品牌搜索和直接访问只能作为辅助信号，不能全部算作 GEO 带来。

### 2.5 用对照和复测判断哪项工作值得继续

Ethan 的建议不是只看发布前后曲线：先记录基线，留出不改动的问题/主题作为对照，再分别测试页面、视频或社区工作，观察后复测；因为即使不改内容，答案与整体使用量也会波动。[G1 32:00–32:59、44:19–46:13](https://www.youtube.com/watch?v=iT7kq-R3Gjc&t=1920s)

**本项目落地**：实验以主题/页面为单位，避免同一页面影响多个问句造成测试组和对照组互相污染。预先确定问题集、问法、市场、语言、产品界面、时间、成功口径和观察周期；结论用“观察到变化/方向性证据”，不是单次出现就证明方法有效。

## 3. 五个判断变量与对应动作

| 变量 | 需要看到什么 | 条件 → 动作 |
| --- | --- | --- |
| 真实问题与购买/使用阶段 | 客服/销售/搜索原问题，站点与语言，已有答案 | 无问题证据 → 先做小规模问题研究；相同意图多问法 → 合并为主题而非批量薄页 |
| 原始资料与答案缺口 | 产品事实、演示、限制、作者/更新记录 | 有问题无证据 → 待补资料；有证据但页面没回答 → 改具体段落/图示/视频说明 |
| 来源与内容形式 | 原始回答、实际引用 URL、来源类型、内容差异 | 引用集中在某类资料 → 为该类型准备真正有用的内容，不保证可付费买到引用 |
| 地区/问法/界面差异 | 每次采样的市场、语言、模型/产品、时间、问法 | 条件不一致 → 分组不混算；单次缺席 → 复测，不立刻批量改站 |
| 引用与业务结果 | 提及、引用、引荐访问、合格行为分别记录 | 有引用无访问 → 检查链接与问题阶段；有访问无转化 → 回到承接页/产品，不虚增发布量 |

## 4. 用户自己的号池与 AdsPower 方法放在哪里

**用户已明确表达的做法/偏好**：GEO 使用号池、AdsPower，并希望体现指纹浏览器、指纹手机与账号策略。这里保留其作为操作组织方式。

**本次没有新核验的事项**：本轮没有读取真实 AdsPower 账号、设备配置、授权清单或历史发布回执；因此不能声称这些环境均已配置、长期发布成功，或它们直接提高了引用。

**与专家方法衔接的执行设计**：

```text
Question & Evidence → Canonical Answer → Platform Version → Review
                                                         ↓
Account Role → Approved Browser / Device → Publish → Public Readback
                                                         ↓
         Index Check → Mention / Citation → Referral → Qualified Action
```

账号角色按品牌、语言、市场、负责人和授权用途划分；浏览器/手机用于让操作者进入正确账号并保留任务上下文。环境数量不是独立用户数量，不能用来伪装口碑、独立推荐或规避平台限制。只有本次任务确需发布时才进入环境；“研究/写草稿”不触发发帖。

任务台账字段：`task_id, account_role, environment_ref, authorized, platform, market, language, content_version, evidence_refs, canonical_url, submitted, post_url, verified_at, public_readback_matches, failure_reason, next_owner`。环境只存内部引用，不公开账号口令、代理配置、设备标识或私人资料。

## 5. Agent 与工具方案：先做可核对的工作

| 能力 | 输入 | 输出 / 完成标准 |
| --- | --- | --- |
| 问题整理 | 已授权且脱敏的客服/销售记录、搜索查询、用户给定问题 | 去重主题、原问题来源、市场与用户阶段；不把模型生成问句当作真实流量 |
| 答案与素材 | 获准公开的商品资料、演示与现有页面 | 修改草稿、逐项证据、图/视频任务说明；未知事实留待补充 |
| 来源观察 | 当前问答界面可见回答、引用链接或获准的跟踪导出 | 逐次观察记录；保存真实被引用 URL，不从答案臆测来源 |
| 分发台账 | 账号角色、环境引用、审批范围、内容版本 | 发布提案或已授权执行回执；重新打开帖子核对身份、正文、媒体、地址和公开状态 |
| 效果判断 | 预先固定的问题集、基线/对照、引用记录、站点分析 | 对比记录，指出波动与缺失；报告和真实转化分开，不推断训练数据已改变 |

工具选择：使用当前可用浏览器、搜索和用户授权的分析导出；有现成连接器就复用。写入用用户已授权的发布能力，执行后回查。API 查询与消费端真实回答不能混成同一份“排名”；验证码、权限不足、受限或不确定提交结果时停止并保留状态，不能换号绕过。

仓库的离线 `distribution` 检查只判断台账证据是否齐全：`PUBLISHED_VERIFIED` 代表有授权、提交记录、URL、时间和匹配的公开回读声明；它不会访问网站证明声明为真，不查索引、不证明引用、更不会发帖。引用抽样与统计仍需真实来源和另行实现。

## 6. 分歧与证据边界

- Lily 强调 SEO 基础的延续；Ethan 更突出长尾问题与站外来源。可共用问题、资料和可访问性检查，再按实际来源拆分工作；不必为了术语给团队重复建两套内容。
- Lily 使用专家性/可信度来指导资料建设；Ethan 对某些专家标记是否已产生算法作用持保留意见。保留可验证身份与原始资料是读者价值和治理要求，不能包装成确定的排名权重。
- “所有 URL 都来自某两个搜索 API”“某模型一定偏好某网站”“一个渠道有固定倍数转化”在视频里只是当时的说明、推测或客户样本，不被采纳为 2026 年系统事实。
- 本次没有复核视频中研究样本、跟踪工具底层采样方式、引用因果效应或各产品最新抓取规范。技术接入、机器人访问和平台政策需执行时再查一手文档；本研究主依据仍为两位专家自己的演讲/访谈，而非官方课程。
