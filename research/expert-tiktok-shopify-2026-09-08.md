## 一、TikTok Shop：先组织能成交的内容，再决定投放规模

### 专家实际在意什么

1. **素材是否带来购买，而不只是播放。** Michelle 在 15:52–16:44 区分可转化内容与偶发爆款；17:53–20:00、25:31–26:24 把广告花不出去或花了没有订单，与可用内容积累联系起来。这只是优先排查方向，不足以证明所有低消耗都由素材造成。[T1](https://www.youtube.com/watch?v=DBpGheWsBGM&t=952s)
2. **达人与商品、人群是否匹配，样品最终有没有变成内容。** 她在 20:00–21:38 用大学饰品案例说明集中产品和对应人群；30:43–31:25 强调样品筛选、跟进、教育仍需要人。不要把合作质量降成发送邀请数量。[T1](https://www.youtube.com/watch?v=DBpGheWsBGM&t=1200s)
3. **库存、履约和佣金能否支撑内容传播。** 14:23–15:38 倾向先用已有库存试验；34:47–35:54 要计入商品成本和履约因素；38:14–38:53 提醒佣金变化会影响创作者关系。这些是经营约束，不是平台门槛。[T1](https://www.youtube.com/watch?v=DBpGheWsBGM&t=2087s)
4. **品牌自己的表达不能全部外包。** Gracey 在 17:19–19:57 讲品牌回应评论、解释生产过程与创始人故事；21:04–21:17 指出手机级拍摄也能承担表达。素材真实、解释清楚，比统一拍成精致广告更重要。[T2](https://www.youtube.com/watch?v=WdOsO4O-I4k&t=1039s)
5. **内容吸引力之外，购买路径也会断。** Gracey 的 10:13–10:42 提到履约疑虑；21:56–22:16 讲缺货。遇到有兴趣但无成交，应检查商品是否还能买、配送承诺是否清楚，不能只换开头。[T2](https://www.youtube.com/watch?v=WdOsO4O-I4k&t=1316s)

### 可执行的四项工作

以下是本次根据访谈推导的实现方案，不冒充专家原话或已部署系统。

|工作|输入与诊断条件|Agent 应替代的具体步骤|输出、人工边界与完成核对|
|---|---|---|---|
|上下架与经营准备|选定 SKU、市场、变体、库存、补货周期、配送、售价、成本、退款、样品及佣金；资料缺失或贡献空间不明则不进入放量建议。|合并商品与履约表，指出缺货、不可购买、承诺矛盾和成本缺项；把阻塞分成商品资格、库存履约、资料待补、内容待测。|输出逐 SKU 准备清单及上架/停售建议。上架、价格、佣金、库存变更必须确认；用目标市场商品页及卖家后台回读，不把接口接受当成可购买。|
|Listing 与视频承诺一致|实物、批准卖点、当前 PDP、关联视频、SKU/变体。视频讲 A 配件但 PDP 实际不含，或镜头/链接指向不同规格时阻止发布。|逐条连接「视频承诺—商品事实—页面位置」，生成事实差异与改稿，不猜认证、效果和配送；优先讲清谁用、怎么用、买到什么。|输出有证据的页面改稿与素材修正清单。最终核对变体、价格、配件、商品链接和移动端显示。访谈不足以支撑一套关键词排名公式，不能包装成已验证 SEO 秘方。|
|视频与创作者合作|品牌评论、真实使用问题、达人受众/内容、寄样、收样、发布、授权、订单。区分未回信、收到未拍、已拍未授权、已发布未成交。|归类用户问题；按匹配理由整理候选；生成真实演示 brief、镜头清单和跟进草稿；记录样品到发布各阶段，不用总播放量掩盖断点。|输出候选依据、脚本、样品队列与授权记录。人负责关系、费用、寄样和发布决定；禁止虚构使用体验、无授权复用，以及默认批量私信。|
|广告测试与放量|按一致窗口整理 SKU、素材、自然/付费来源、花费、订单、退款、佣金、成本、可售库存；区分低消耗与高消耗无成交。|低消耗先列资格/授权/供给/设置检查项；有点击无购买再看承诺、价格、配送；比较同类条件下的素材与成交，给下一轮只改一个主要变量的候选。|输出保留/重做/观察/减量/放量候选和理由，不自动改预算。执行前确定观察期、可承受损失、预算上限与审批人；执行后回读状态和结果，不能以面板 GMV 宣称广告增量。|

### 不能照搬的部分

- Michelle 提到的固定内容数量、每天大量邀约、当时 PSA/VSA 路径，均不写成当前规则或 Agent 固定参数。素材数量只是能力供给的一个维度，不能替代质量、授权、成本和真实结果。
- Gracey 的创作者案例说明「只找达人、品牌自己不表达」并非必然正确。合作内容与品牌答疑应互补。
- 单次爆款、高佣金或达人自述成交，不足以证明下一 SKU、国家、价格带能复用。同样不能把归因订单当增量订单。

### 最小技术路径

先使用已授权的 Seller Center / Ads Manager 导出、商品页、素材文件和合作台账；读取 CSV 与浏览器公开/已授权页面，即可产出上述建议。不要为了输出报告先造一个跨平台接口层。

若未来接 API，TikTok Shop 的[接口文档](https://partner.tiktokshop.com/docv2/page/methods-and-endpoints)与[店铺连接文档](https://partner.tiktokshop.com/docv2/page/connecting-shops)要求区分区域入口和卖家授权。商品/订单授权不证明已有广告、达人私信或素材权限；逐项验证权限后才增加连接，缺少权限就停在报表和人工操作，不承诺“全自动通用 API”。

## 二、Shopify：让广告进来的用户完成理解、选择与下单

### 专家实际在意什么

1. **进来后能否迅速理解商品。** Shaun 在 03:05–03:47 强调商品、价值、证明的清晰度；03:49–05:54 指出菜单若把购物路径藏起来，会增加阻力。不是所有店铺都要删 About，而是主要购买路径不能被次要导航淹没。[S1](https://www.youtube.com/watch?v=Ha6spU4Weyo&t=185s)
2. **移动端真实可操作，而不是桌面截图好看。** 08:16–09:31 指出聊天、积分、评价等悬浮层会挡住菜单和购买；14:33–16:21 讨论移动图片浏览与图中信息。要实际点选规格、加购、打开购物车后再判定。[S1](https://www.youtube.com/watch?v=Ha6spU4Weyo&t=496s)
3. **媒体应解释商品和价格。** 13:16–14:33 讲使用对象、场景与套装内容。好看的商品照若没讲清买到什么，不能替代购买信息。[S1](https://www.youtube.com/watch?v=Ha6spU4Weyo&t=796s)
4. **页面长度应服从购买决策。** Ezra 在 00:22–01:35 区分低解释成本、已被说服或复购用户，与需要故事、演示、教育的商品；不能把所有流量都导向同一种长页。[S2](https://www.youtube.com/watch?v=aYNvOEHeSgo&t=22s)
5. **购买区域、媒体和组合销售各有任务。** 07:50–09:54 讲场景/细节图及明确的购买信息；09:55–12:17 涉及互补组合、规格与 CTA。04:39–06:18 的设备差异提醒，应结合每次访问价值诊断，不只盯全站转化率。[S2](https://www.youtube.com/watch?v=aYNvOEHeSgo&t=470s)

### 可执行的四项工作

|工作|输入与诊断条件|Agent 应替代的具体步骤|输出、人工边界与完成核对|
|---|---|---|---|
|上下架与承接可用性|投放 SKU、商品/库存导出、变体、价格、目标市场、渠道可见性、配送与退换。广告落地页有商品不等于目标市场能买。|连接广告入口与目标商品/变体；检查缺货、不可达、价格或版本差异；对指定 SKU 生成改动前后的差异，不默认全量导入。|输出发布/库存/市场待处理清单。确认后才写；回读目标市场页面、变体选择、加购与购物车。禁止因一次检测就全店下架。|
|Listing / PDP 结构|商品复杂度、客单价、是否复购、流量入口与购买疑问。用户已理解却被长叙事拖住，与用户没理解就见购买按钮，是不同问题。|先判定页面承担“快速购买”还是“解释与说服”；梳理商品是什么、适合谁、怎么选、有什么证据；给模块顺序与短/长页候选。|输出页面 brief、保留/移动/补充清单和单变量测试计划。人确定品牌表达与 offer；不把某版页面称为已经跑赢。|
|商品媒体与视频|真实商品资料、尺寸/套装、场景、使用演示、现有主辅图与视频、设备预览。缺少规格/配件解释，或图片中物件与实际销售不一致时退回。|建立媒体覆盖表；指出需补拍/补标注的信息；生成源于事实的分镜、alt 文本与图片顺序；检查移动端裁切、字幕与加载。|输出资产清单、缺口、分镜与审核备注，不虚构评价和材质。最终浏览器逐图/逐段核对，实际播放、缩放、滑动，不只检查文件存在。|
|广告与页面诊断|来源/广告承诺、设备、落地页、事件、订单、退款、折扣、毛利、重复购买。先确认事件口径和页面可操作，再评估 offer。|将流量质量、理解成本、规格/加购阻塞、结账阻塞分开；对移动遮挡、入口不一致和媒体信息缺口给截图证据；候选修改只解决一个主要问题。|输出按影响与证据排序的改动建议。跟踪匹配来源/设备的贡献或每次访问价值，避免用混合 CVR 证明创意优劣；不同时改预算、价格、页面后再编因果。|

### 两个重要反例

- **更长不一定更好。** Ezra 明确按购买理解成本选择页面；适合新客教育的长页，对已有明确意图和复购的访客可能多余。
- **更多插件、促销和动效不等于更好。** Shaun 的移动端遮挡与 17:24–18:28 的品牌/短期转化讨论提醒：优化不能把阅读、导航和品牌可信度牺牲掉。其案例不足以证明某类插件必然无效，需在当前页面诊断。

### 最小技术路径

先用 Shopify 产品 CSV、单独的库存资料、订单导出与浏览器审核。官方支持[商品导出](https://help.shopify.com/en/manual/products/import-export/export-products)，但图片本体不在 CSV 内；[CSV 字段存在变体依赖](https://help.shopify.com/en/manual/products/import-export/using-csv)，不能随意重排破坏商品、变体、图片对应关系。导入是实际商店写操作，不是预览步骤。

需要定期同步时，再基于商家授权设计 Admin API 读取；本研究没有生成 GraphQL、没有验证用户安装的应用权限，也没有宣称已有 API 接入。报告/截图/差异输出可以先独立运行，写入与发布需额外确认。

## 三、落成 Skill 时应保留的具体合同

每次以一个明确 SKU、市场、观察窗口和问题开始，而不是先跑全平台“智能诊断”。

```text
Scoped task + approved source files
    → verify SKU / market / time window / permissions
    → separate missing evidence from observed problems
    → diagnose a specific break in the buying path
    → produce a versioned draft or recommendation
    → human approval for publishing, outreach, price or budget
    → apply only the approved change
    → reopen the destination and record what actually changed
```

建议交付字段：任务、平台、店铺/市场、SKU/变体、来源与时间、当前状态、发现、依据、拟改动、预期验证方式、审批状态、实际执行结果。保留原始记录，不让语言模型填补缺失利润、授权、库存、订单或用户反馈。

失败处理必须具体：文件字段不齐→列缺项而非估填；币种/窗口不一致→阻止跨行比较；页面状态与导出冲突→标记冲突并重新读取；权限不够→给人工步骤；素材未授权→不发布；写入部分成功→逐项记录，不自动重跑全部；没有足够观察样本→输出待观察，不强判放量或暂停。

## 四、尚不能从这次研究推出什么

- 两平台没有一套通用的“上架—素材—广告”最优参数。TikTok Shop 多一个创作者、样品、授权与内容分发链；Shopify 的承接设计和来源/设备差异更直接由商家控制。
- 四段访谈不是严谨的增量实验，也不覆盖所有类目和市场。历史广告产品名、平台支持范围、商家资格、隐私政策和 API 权限需另查当前官方规则。
- 没有证据证明贾敬秋使用过上述专家的具体方案、达到访谈中的收入规模，或拥有他们推荐工具的授权。本报告只能作为拟采用方法的研究依据；已有个人交付另用代码、操作记录和真实案例举证。
