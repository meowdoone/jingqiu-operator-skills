# 美客多与 Shopee：从实操视频整理的运营判断与 Agent 方案

研究日期：2026-09-08。状态：**研究与执行方案，未连接店铺、未改商品、未投广告。**

这次读的是巴西卖家与代运营从业者的葡语原视频字幕。不是墨西哥、阿根廷或 Shopee 东南亚各站点的完整打法；税费、物流、目录规则和广告功能不能直接跨国复制。作者的案例成绩、算法解释和经验阈值不等于独立验证的事实，更不是贾敬秋已取得的业绩。

## 2. 美客多：先判断商品是否适合投，再决定怎么投

### 2.1 五个主要变量

1. **可承担的广告成本**：ACOS 看广告归因销售，TACOS 看该渠道总销售；两者一起看，避免用大量自然销售掩盖某个广告商品亏损。来源：[M2 04:36–06:24](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=276s)。
2. **目录位置与竞争条件**：自有品牌目录与多人竞争同一目录要分开判断；没有持续竞争力时，先处理供货、报价和差异化，而不是只加预算。目录展示条件是作者在 2024 年的说法，执行前必须核对当前站点和该商品状态。来源：[M2 06:29–10:25](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=389s)。
3. **商品成熟度、客单价与点击成本**：Lucas 按销售表现分组，再处理高低客单差异；低曝光新品不与成熟畅销款共用一种判断。来源：[M2 10:47–15:29、17:10–18:28](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=647s)。
4. **库存与实际送达条件**：Bruno 不给即将缺货、且自然销售已经充足的商品继续引流；同一物流项目在不同地域的竞争条件也可能不同。来源：[M1 11:24–11:41](https://www.youtube.com/watch?v=6Pl1jHBlvqc&t=684s)、[M2 28:57–29:39](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=1737s)。
5. **购买前的问题是否被说明白**：关键词、主图、价格、配送和商品证据一起构成报价；Lucas 建议从买家问题提取常见疑问，放进图片说明；Clips 应帮助购买判断。来源：[M2 29:48–33:19](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=1788s)。

### 2.2 条件 → 判断 → 动作

下表“动作”是把专家经验整理成可审核任务，并非已经在店铺执行。

| 工作 | 判断条件 | 建议动作与停止条件 | 来源 |
| --- | --- | --- | --- |
| 上架准备 | 规格、目录归属、库存或送达条件不清楚 | 先补商品资料与类目/目录核对单；存在歧义不自动上架。新商品与已稳定销售商品分组，不能因没有历史订单直接否定新品 | M2 06:29–10:25、32:00–33:19；资料校验与人工放行是本研究增加的执行要求 |
| Listing | 有点击但购买不足；页面只有一张图或关键信息缺失 | 将买家问题按尺寸、兼容性、用法、包装、配送归类；只用商品事实答复；生成图片/文案修改对照，先改单个主要问题，再观察 | M2 29:48–33:19 |
| 视频 / Clips | 商品使用、尺寸或功能仍难从图文理解 | 生成“一个购买问题 → 对应真实演示 → 应展示的细节”短片说明。没有实物证据的功能不生成“实测”结论；Clips 是否可上传、尺寸/时长待站点核对 | M2 32:00–33:19；不是已验证的短视频投流增长公式 |
| 广告建组 | 高低客单或成熟度差异大，少数商品吃掉展示 | 建议按表现与客单拆组；逐项查看没有展示的商品，另列小规模测试，不把“没得到流量”直接写成“商品不行” | M1 11:48–12:22；M2 10:47–18:28 |
| 预算 | 花费尚未触及预算，却只想通过大幅提高预算放量 | 先查报价、目录、展示竞争和成本目标；预算是风险上限，不是“告诉平台我有钱”。有余量不等于一定有额外需求 | M2 19:57–22:50 |
| 暂停 / 恢复 | 商品缺货、供应即将中断，或在成熟观察期内持续低于经营要求 | 缺货与表现差分别进入队列；前者优先库存/恢复计划，后者先核对归因和商品分组，再提交广告暂停建议。**暂停广告不等于永久删除 Listing** | M1 11:24–11:41、14:38–17:20；不可逆删除的限制为本研究设计 |

### 2.3 分歧不能省略

- Bruno 偏好很低的 ACOS；Lucas 指出新品、服装和不同客单可接受的阶段成本不同。因此不把“3% 或 5%”硬编码成所有商品的门槛。广告目标来自该商品利润、阶段任务和能承受的试错费用。[M2 15:34–17:01](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=934s)
- Lucas 给出每组约 8–15 个商品的管理经验，Bruno 认为自己的低 ACOS 场景常只有少数商品真正拿到展示；这是账户结构经验，不是平台数量限制。[M2 12:24–15:29](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=744s)
- 作者谈及“广告积累自然排名”“移动商品保留学习”等机制，没有提供平台证明或对照实验。只记录为待验证假设，不据此保证自然排名提升，也不为了所谓学习强行维持亏损。[M2 23:29–27:11](https://www.youtube.com/watch?v=ZhSOevbUKmo&t=1409s)
- M1 中讲目标 ACOS 后，又展示实际 ACOS 高于目标；系统必须分别保留 `target_acos` 与 `actual_acos`，不能把目标当作实际成本上限。[M1 17:34–17:45](https://www.youtube.com/watch?v=6Pl1jHBlvqc&t=1054s)

## 3. Shopee：先选有转化条件的商品，再调广告模式

### 3.1 五个主要变量

1. **封面与真实购买意图**：Vitor 从封面、价格、标题到物流/优惠解释点击；特别反对以低价变体或含糊图片骗取点击，因为进页后承诺不符会损害转化。来源：[S2 07:08–12:16](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=428s)。
2. **商品证据、变体库存、完整成交条件**：尺寸、材质、功能、视频、可买颜色与送达条件共同影响选择；文字描述补图片未讲清的问题。来源：[S2 12:51–19:19](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=771s)。
3. **已付订单转化与样本量**：Vitor 导出完整月份的商品表现，用订单转化找候选，同时核对库存和利润。高转化率但只有极少访问只能列为待测，不直接认定优胜；这一样本限制是本研究补充。来源：[S2 20:29–27:52](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=1229s)。
4. **广告后的贡献利润**：Caue 和 Vitor 都把商品成本、费用等放回成本判断；ROAS 较高也可能不足以覆盖该商品的经营要求。来源：[S1 23:48–25:35](https://www.youtube.com/watch?v=ECli2Z1iulA&t=1428s)、[S2 32:38–37:41](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=1958s)。
5. **实际广告模式、观察期和预算消耗**：2024 的关键词手动方法与 2025 的 GMV Max 目标 ROAS 方法必须标明版本；先识别当前账号提供什么，再运行对应判断。来源：[S1 15:05–21:44](https://www.youtube.com/watch?v=ECli2Z1iulA&t=905s)、[S2 28:14–32:24、39:10–50:34](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=1694s)。

### 3.2 条件 → 判断 → 动作

| 工作 | 判断条件 | 建议动作与停止条件 | 来源 |
| --- | --- | --- | --- |
| 上架 / 变体 | 封面、标题所指颜色/组合与可买变体不一致 | 建立 SKU 与图文/价格/库存一一对应表；先修正承诺，不把便宜配件混作主商品引流；缺少资料先保存草稿 | S2 11:38–15:13；草稿放行是本研究增加的执行要求 |
| Listing | 有展示少点击 | 核对搜索意图、封面辨识度、价格和送达条件；一次提交一个主要修改假设。不能仅凭 CTR 下降就自动加价或降价 | S2 07:08–12:16 |
| Listing / 视频 | 有点击少付费订单 | 检查尺寸、电压、使用方式、包含物、可买规格、配送；视频用于消除具体疑问。只输出经商品资料支持的镜头与说明，不虚构效果或评价 | S2 12:51–19:19 |
| 广告选品 | 只有销售额排序，没有利润/库存/付费转化数据 | 导出商品表现，按 item 与 variation 区分；把可供货、利润可承受、转化有足够观察的商品列为优先测试候选 | S2 20:29–27:52 |
| GMV Max 放量 | 实际回报达到要求且经常用完预算，库存/履约可支撑 | 提交小幅预算增加与回查时间；若预算未用完，先查目标回报、Listing 和需求，不同时改多项。不采用“无限预算”作默认设置 | S2 44:29–49:34；幅度/限额/回查为本研究增加的约束 |
| GMV Max 利润 | 订单量足够但广告后的贡献不足 | 评估更高回报目标、价格或商品页面修改，明确可能牺牲成交量；如果已亏损，不以“学习期”无限延后止损 | S2 35:40–37:41、49:35–50:34 |
| 旧关键词模式 | 当前账号确实仍支持关键词与对应报表 | 保留相关词，排除与商品不符的建议词；在可比较窗口看词级成本与利润。Caue 的七天、2% CTR、小额加价只是当时的测试经验，不能跨站点硬套 | S1 18:10–20:46、21:42–26:36 |
| 暂停 / 恢复 | 主要变体断货、商品承诺不成立、成本不可承受 | 分清商品不可售与广告无效；优先提交对应暂停/修复队列，补货及事实核对后才能建议恢复，不因为一天少单永久删除商品 | S2 14:47–15:13、27:04–27:52、38:19–38:46；恢复条件为本研究设计 |

### 3.3 不应直接复制的地方

- Caue 的 2024 片讲手动关键词、位置与逐词出价；Vitor 的 2025 片讲 GMV Max，并提到产品手动模式退场。时间与账号能力不同，不是把两套按钮叠加就得到“完整自动化”。[S1 16:47–21:44](https://www.youtube.com/watch?v=ECli2Z1iulA&t=1007s)、[S2 52:50–53:05](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=3170s)
- Vitor 偏好目标 ROAS，因为其自身利润结构不适合部分自动出价结果；这是商品经济约束，不是所有账户都该使用同一模式。[S2 35:40–39:19](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=2140s)
- 片中的费用、最低预算、预估回报范围，以及对税务的口头描述都不能当作 2026 年各站点事实；实现必须使用用户当前费用表和财务口径，不照搬视频示例。
- 自动字幕把 ROAS 多次识别为人名/普通词，金额也有错漏；指标必须来自实际导出文件。店铺营销数据与作者使用的 AvantPro 扩展数据分开记录，外部估计不作本店收益。[S2 17:51–18:31](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=1071s)

## 4. 适合整理为 Agent 的最小工作范围

以下是本研究提出的设计，不是专家声称已交付的系统，也不是现有 API 已验证可用。

### 4.1 输入与输出

| 输入 | 最小要求 | 输出 |
| --- | --- | --- |
| 店铺与国家 | 平台、站点、币种、时区、店铺 ID、授权范围、当前可用功能 | 本次可读/可写能力清单；没有授权不执行 |
| 商品事实 | item/SKU/variation ID、标题/规格、图片与视频授权、库存、补货时间、配送条件 | 上架准备检查、缺口清单、Listing 前后对照、视频任务说明 |
| 商品与广告报表 | 窗口、归因口径、花费、展示、点击、已付订单、归因销售、商品总销售 | 数据核对结果、候选商品分组、待观察/待调整清单 |
| 经营要求 | 实际商品成本、平台费用、物流/退款等变动成本、最低贡献、可承受试验费用 | 逐商品广告成本范围，不输出统一“行业 ROI” |
| 执行边界 | 允许的 SKU/广告 ID、最高总费用、单次变化范围、批准人、到期时间 | 具体改动提案、风险、依据、批准记录与执行回执 |

计算先于文案：在**同币种、同时间窗、同收入与退款口径**下，广告前贡献 = 净收入 − 非广告变动成本；广告后贡献 = 广告前贡献 − 广告花费。ACOS = 广告花费 / 广告归因销售；TACOS = 广告花费 / 对应渠道总销售。分母不同必须显式标注，不能直接把商品级成本与全店收入拼接。目标 ROAS、平台估算、实际 ROAS 三列分开；零分母和缺字段返回“无法判断”。

### 4.2 工具方案

优先接用户已有 Seller Center / ERP 导出文件，做一次只读报告；不为每个平台先造一套连接框架。S2 的实操本身已采用商品报表导出再分析。[S2 21:50–22:27](https://www.youtube.com/watch?v=3UEIV-o4FF4&t=1310s)

- 数据读入：已有 CSV/XLSX 解析能力；字段映射、ID 去重、币种和时间窗校验用确定性规则。
- 内容工作：模型只整理买家问题、商品文案与镜头提案；输出中每个功能/规格回指商品证据，未知值留空。
- 资产检查：已有媒体检查工具核对时长、尺寸与声音等；上传规格由当前站点核实，不能从旧视频推导。
- 平台执行：先用商家已授权工具或现有 ERP。若采用 API，必须另行核实该国家、卖家类型、认证、权限和真实写入字段；本研究**没有验证 Mercado Ads / Shopee Ads 写接口可用**。缺少接口时可按明确任务使用当前浏览器后台，但不把点击提交当作已保存。
- 每次发布或预算修改，重新读取真实对象 ID、状态与生效值；接口/页面不提供可核对回执则停在待确认。预算、上下架和批量修改需本次具体授权。

```text
Account & Country → Product Facts → Report Check → Decision Draft
                                      ↓                ↓
                                 Missing Evidence    Approval
                                      ↓                ↓
                                     Hold       Apply → Read Back
```

### 4.3 至少应有的验收样例

1. 广告产品子集的自然销售，不能误当整个店铺自然销售（M1 03:50–05:16）。
2. 目标 ACOS 低，但实际成本高：显示偏离，不宣称系统已经“卡住 ROI”（M1 17:34–17:45）。
3. 目录未具备竞争条件：先查目录，不直接加预算（M2 06:29–10:25）。
4. 高客单产品挤占低客单展示：输出分组候选而不是统一关闭低曝光商品（M2 17:10–18:28）。
5. 封面颜色断货：暂停该变体相关承诺/引流建议，不把其他可售变体全部删除（S2 14:47–15:13）。
6. 一个访问产生一单的高转化：样本不足，只能待测，不能直接扩量（本研究补充）。
7. 新账号只有 GMV Max：不调用旧关键词/位置规则（S1/S2 功能差异）。
