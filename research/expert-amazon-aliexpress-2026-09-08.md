## 2. Amazon：最值得留下的五个变量

| 变量 | 实操来源与关键段落 | 可采用的判断 |
| --- | --- | --- |
| 库存与可售性 | A1 08:18 起，先检查库存 | 商品不能买、即将断货或配送不成立时，先处理供给；广告优化不能代替可售修复。 |
| 预算集中在哪些词 | A1 08:36–10:04、14:18–16:30 | 先查高花费计划与搜索词，检查遗漏否词，也检查错杀的好词；必要时隔离预算，而不是为了结构漂亮重建全部计划。 |
| Listing 的点击与购买阻力 | A2 15:12–16:32、20:26–23:54 | 点击前检查主图、价格和商品表达；点击后检查规格、证据、疑问与视频是否帮助购买。流量与转化分开诊断。 |
| 目录优先级与利润金额 | A2 26:33–29:04、36:24–37:41 | 预算和运营时间优先给可盈利的主力 SKU 与少量候选；ACOS 下降但利润金额减少，不一定是改善。 |
| 数据是否足以改变动作 | A1 23:26–24:44、28:01–28:18；A2 34:06–35:31 | 分时投放需要足够订单数据；先修基础问题，再研究小时级调整。增长、效率和转化修复是不同阶段。 |

### 条件 → 动作

- **上下架**：同站点 SKU 的库存或可售状态异常 → 先识别缺货、价格/配送问题、审核或商品属性问题，再提出对应动作。临时停止自己的 offer，与删除共享 ASIN 是不同操作。A1 支持库存优先；具体平台状态语义使用当前后台/接口核验，不由访谈推导。
- **Listing**：搜索意图相关，但点击率弱 → 做商品真实主图或价值表达候选；点击足够而转化弱 → 从规格、价格、配送、差评和问答找障碍。一次测试记录改了什么及对应 SKU；不能把同期广告、价格和图片全部变化后的结果归因给图片。
- **视频**：购买疑问能用演示回答 → 将“用途/功能/尺寸/操作证据”排成短片，而不是先生成漂亮镜头。A2 20:26–21:50 强调视频帮助理解收益和使用方式。先核真实商品、交付包装、权利和上线资格。
- **广告**：预算被少数高成本词吃掉 → 拆开看搜索词相关性、竞价和预算限制；新计划小范围比较，保留有效旧计划。A1 33:42–34:10 明确反对把正在工作的计划全部停掉。扩量判断同时看退款后利润、库存承接和新增花费的回收，不只看平台归因销售。

### 两位实操者并不完全同意

Steven 偏重计划分组、搜索词否定和可控预算；Mina 从整个商品漏斗、目录分层与利润看投放。适合组合使用：先确保商品能卖且表达清楚，再处理预算分配。不能把 Steven 的“每组少于五个词”“Broad 更便宜”，或 Mina 的示范日预算、搜索量筛选数字当跨账户默认值。Mina 对高 ACOS 可能带来自然销售的解释属于待检验假设，不能作为长期亏损免责理由。

## 3. AliExpress：卖家经营，而非从 AE 采购代发

Óscar 演示的是西班牙商家在 AE 开店、商品创建和配送；E2 是巴西有本地库存的卖家。它们不能直接证明中国跨境、自运营、半托管或全托管账户当前拥有相同功能。

### 四类工作如何落地

**上下架。** E3 最有价值的不是旧后台按钮，而是作者提到误用测试运费模板，导致一单袜子免费寄往俄罗斯（02:29–02:42）。可复用动作是：商品提交前锁定目标 SKU、市场、配送模板和费用；提交后用不同地区实际核验。暂停、审核失败、缺货分别处理，批量任务要有逐 SKU 结果，不能只报告“请求成功”。

**Listing。** E1 把站内关键词与用户疑问整理成工作表；E3 再将词、属性、变体和品牌资质落实到商品。站外搜索工具只提供补充线索，不冒充 AE 自有需求数据。自动翻译后应核材质、尺寸、单位与承诺，不能由模型补不存在的规格。

**视频素材。** E3 26:15–26:58 演示详情编辑器可放视频块；E2 讲的是图片真实和使用场景。当前资料不足以证明一套 AE 视频投放回报规律。因此“从商品事实与购买疑问生成演示分镜”是我们的实现建议，不标为专家已验证视频增长方案；当前账号的上传位置、审核、规格另核。

**广告与推广。** E4 的重点是店铺促销、活动和成交佣金，不是完整的当代付费竞价体系。佣金获客与 CPC 花费必须分账；参加活动也不能一律叫“广告放量”。若用户要自动出价，先取得具体国家、经营模式、推广产品、当前报告和权限，现有证据不足时只输出计划与缺口，不虚构 API。

### 不同经营模型带来的差异

Óscar 更关注站内选词与商品发布配置；巴西课程更关注本地物流选择、免费/部分包邮和商品总报价。前者帮助解决“找到和理解”，后者帮助解决“买得起、送得到”。二者不是互相替代。AE 中国跨境及托管模式的当前专家实操、具体竞价工具和视频增量效果仍需补证。

## 5. Agent 实现合同（本研究提出，未声称已经实现）

### 先读取什么

最小任务范围：平台、国家、账号/经营模式、准确 SKU/ASIN、请求动作、观察窗口、币种与授权范围。只针对请求的工作读取：

| 工作 | 输入与连接键 | Agent 交付 |
| --- | --- | --- |
| 可售诊断 | SKU/ASIN、库存、可售状态、审核问题、配送/模板、更新时间 | 按 SKU 排序的问题清单；建议动作、阻塞原因和需人工确认的变更 |
| Listing | 商品事实与证明、属性/变体、现有文案、来源明确的关键词及评价问题 | 文案差异、事实对应表、属性缺口；不直接覆写 |
| 视频 | 目标 SKU、真实图/规格、素材授权、目标位置、购买疑问 | 分镜、台词/字幕、必须保真的部位及待拍证据；制作与上线是后续独立动作 |
| 广告/促销 | 日期、账户、SKU、campaign/ad group/search term、花费、订单、退款、成本、归因窗口 | 诊断及候选调整、估算影响范围、观察期、停止条件、批准状态 |

### 技术方法

1. 优先使用获授权报表/连接器；无连接时处理本地 CSV/JSON。字段不存在就列缺失，不从页面总计推造明细。
2. 用确定性代码完成日期/币种校验、SKU 连接、去重与成本计算；语言模型负责商品事实抽取、问题归类、文案和解释。
3. 分开保存外部关键词/竞品样本、自有经营结果与平台归因结果。对齐观察窗口后才比较；成本/退款缺失时不输出利润结论。
4. 变更提案包含准确目标、当前值、拟改值、证据、预算或价格影响、有效期和回退资料。权限只读则结束于建议/草稿。
5. 真正执行需要本次明确授权与可用工具；先保存原值，限定单个 SKU/小批次，再读取最终后台和前台状态。接口 accepted 与前台可买分别记录。
6. 账号身份不明、币种冲突、数据截断、权限失败、提交结果不确定时停止相关写入；查询状态，不盲重试或重复创建。

状态使用 `INSUFFICIENT_DATA / REVIEW / DRAFT_READY / AUTHORIZED / SUBMITTED / VERIFIED / BLOCKED`，防止把一份提案包装成全自动运营系统。样本充足度取决于原有订单密度、波动、归因延迟与可承受损失，不设所有平台通用的“几次转化即可放量”。
